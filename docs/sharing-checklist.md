# Sharing the portfolio

Your current delivery preference is local-only. No remote, commit, tag, public URL
or application has been created. The local package is suitable for a source review;
a reader still needs access to it to assess the project.

Before using a project link in applications:

1. Run the full verification and retain the source/evidence bundle.
2. Follow the five-minute reviewer guide from an extracted source folder.
3. Choose the actual sharing method: attach the portable candidate when appropriate,
   or later create a reviewed public/private repository. Do not use an invented URL.
4. If you choose repository publication, review the source, choose a license, make
   an initial commit, configure the intended remote and check hosted CI after push.
   The implementation-guide PDF, dependencies and large local raw captures are
   excluded from source packaging; the compact evidence is included.
5. Add a short screen recording or terminal walkthrough when visual review is
   available. No video or automated browser-visual pass is claimed currently.
6. Select the engineering or research-oriented resume entry. Keep historical,
   synthetic and core-only measurement qualifications when using the speedup.
7. Practice explaining the source and trade-offs without prepared answers. A strong
   artifact supports an application; it cannot guarantee screening or interviews.
